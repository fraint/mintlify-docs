---
title: "Anthropic messages"
description: "Send messages to Claude and compatible models using the Anthropic Messages protocol, including system prompts, streaming, and tool use via Volink."
---

The `/v1/messages` endpoint follows the Anthropic Messages protocol and works with Anthropic-compatible clients and Claude-style SDKs. Use this endpoint when you want Claude-style message payloads, a top-level `system` field, or `top_k` sampling control.

## Endpoint

```http
POST /v1/messages
```

## Required headers

```http
x-api-key: YOUR_VOLINK_API_KEY
anthropic-version: 2023-06-01
content-type: application/json
```

Volink also accepts `Authorization: Bearer YOUR_VOLINK_API_KEY` if your client uses bearer authentication. Use one authentication style consistently within a single request. See [Authentication](/api-reference/authentication) for more detail.

## Request parameters

<ParamField body="model" type="string" required>
  Model ID to use. Replace the example value with a model ID enabled in your Volink account.
</ParamField>

<ParamField body="max_tokens" type="integer" required>
  Maximum number of tokens to generate. This field is required by the Anthropic protocol.
</ParamField>

<ParamField body="messages" type="array" required>
  Conversation messages using `user` and `assistant` roles. Each item has a `role` and a `content` field.
</ParamField>

<ParamField body="system" type="string | array">
  System instructions. Anthropic uses a top-level `system` field rather than a message with `"role": "system"`. You can pass a plain string or an array of content blocks.
</ParamField>

<ParamField body="temperature" type="number">
  Sampling temperature. Higher values produce more varied output.
</ParamField>

<ParamField body="top_p" type="number">
  Nucleus sampling value.
</ParamField>

<ParamField body="top_k" type="integer">
  Top-k sampling value when supported by the model.
</ParamField>

<ParamField body="stream" type="boolean">
  Set to `true` to receive the response as a stream of server-sent events.
</ParamField>

<ParamField body="tools" type="array">
  Tool definitions available to the model. Each item describes a callable function.
</ParamField>

<ParamField body="tool_choice" type="object">
  Controls whether and how the model selects a tool.
</ParamField>

## Example

```bash
curl "$VOLINK_BASE_URL/v1/messages" \
  -H "x-api-key: $VOLINK_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-4.5",
    "max_tokens": 512,
    "system": "You are a concise technical assistant.",
    "messages": [
      {
        "role": "user",
        "content": "Explain Volink in one sentence."
      }
    ]
  }'
```

## Response

```json
{
  "id": "msg_xxx",
  "type": "message",
  "role": "assistant",
  "model": "anthropic/claude-sonnet-4.5",
  "content": [
    {
      "type": "text",
      "text": "Volink is a unified AI platform for accessing multiple model providers through compatible APIs."
    }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 18,
    "output_tokens": 17
  }
}
```

<ResponseField name="id" type="string">
  Unique identifier for the message.
</ResponseField>

<ResponseField name="type" type="string">
  Always `"message"` for non-streaming responses.
</ResponseField>

<ResponseField name="role" type="string">
  Always `"assistant"`.
</ResponseField>

<ResponseField name="model" type="string">
  The model that generated the response, prefixed with the provider slug.
</ResponseField>

<ResponseField name="content" type="array">
  Array of content blocks. Each block has a `type` (e.g., `"text"`) and a corresponding field (e.g., `"text"`).

  <Expandable title="properties">
    <ResponseField name="content[].type" type="string">
      Content block type. `"text"` for text responses; other types appear for tool use.
    </ResponseField>
    <ResponseField name="content[].text" type="string">
      The generated text, present when `type` is `"text"`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="stop_reason" type="string">
  Why generation stopped. Common values: `"end_turn"`, `"max_tokens"`, `"tool_use"`.
</ResponseField>

<ResponseField name="stop_sequence" type="string | null">
  The stop sequence that triggered the end of generation, or `null`.
</ResponseField>

<ResponseField name="usage" type="object">
  Token counts for billing and monitoring.

  <Expandable title="properties">
    <ResponseField name="usage.input_tokens" type="integer">
      Tokens consumed by the input.
    </ResponseField>
    <ResponseField name="usage.output_tokens" type="integer">
      Tokens generated in the response.
    </ResponseField>
  </Expandable>
</ResponseField>
