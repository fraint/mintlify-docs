`/v1/messages` 端点遵循 Anthropic Messages 协议,可与 Anthropic 兼容客户端和 Claude 风格的 SDK 一起使用。当您需要 Claude 风格的消息负载、顶层 `system` 字段或 `top_k` 采样控制时,使用此端点。

## 端点

```http
POST /v1/messages
```

## 必需的标头

```http
x-api-key: YOUR_VOLINK_API_KEY
anthropic-version: 2023-06-01
content-type: application/json
```

如果您的客户端使用 Bearer 身份验证,Volink 也接受 `Authorization: Bearer YOUR_VOLINK_API_KEY`。在单个请求中始终保持一种身份验证方式。有关详细信息,请参阅 [身份验证](/api-reference/authentication)。

## 请求参数

<ParamField body="model" type="string" required>
  要使用的模型 ID。将示例值替换为您 Volink 账户中已启用的模型 ID。
</ParamField>

<ParamField body="max_tokens" type="integer" required>
  要生成的最大 token 数。Anthropic 协议要求此字段。
</ParamField>

<ParamField body="messages" type="array" required>
  使用 `user` 和 `assistant` 角色的对话消息。每个项目都有 `role` 和 `content` 字段。
</ParamField>

<ParamField body="system" type="string | array">
  系统指令。Anthropic 使用顶级 `system` 字段,而不是 `"role": "system"` 的消息。您可以传递纯字符串或内容块数组。
</ParamField>

<ParamField body="temperature" type="number">
  采样温度。较高的值产生更多样化的输出。
</ParamField>

<ParamField body="top_p" type="number">
  核采样值。
</ParamField>

<ParamField body="top_k" type="integer">
  模型支持时的 top-k 采样值。
</ParamField>

<ParamField body="stream" type="boolean">
  设置为 `true` 以将响应作为服务器发送事件流接收。
</ParamField>

<ParamField body="tools" type="array">
  对模型可用的工具定义。每个项目描述一个可调用函数。
</ParamField>

<ParamField body="tool_choice" type="object">
  控制模型是否以及如何选择工具。
</ParamField>

## 示例

```bash
curl "$VOLINK_BASE_URL/v1/messages" \
  -H "x-api-key: $VOLINK_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-4.5",
    "max_tokens": 512,
    "system": "You are a concise technical assistant.",
    "messages": [
      {
        "role": "user",
        "content": "Explain Volink in one sentence."
      }
    ]
  }'
```

## 响应

```json
{
  "id": "msg_xxx",
  "type": "message",
  "role": "assistant",
  "model": "anthropic/claude-sonnet-4.5",
  "content": [
    {
      "type": "text",
      "text": "Volink is a unified AI platform for accessing multiple model providers through compatible APIs."
    }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 18,
    "output_tokens": 17
  }
}
```

<ResponseField name="id" type="string">
  消息的唯一标识符。
</ResponseField>

<ResponseField name="type" type="string">
  对于非流式响应,始终为 `"message"`。
</ResponseField>

<ResponseField name="role" type="string">
  始终为 `"assistant"`。
</ResponseField>

<ResponseField name="model" type="string">
  生成响应的模型,带有提供商前缀。
</ResponseField>

<ResponseField name="content" type="array">
  内容块数组。每个块都有一个 `type` (例如 `"text"`) 和相应的字段 (例如 `"text"`)。

  <Expandable title="properties">
    <ResponseField name="content[].type" type="string">
      内容块类型。对于文本响应为 `"text"`;其他类型出现在工具使用中。
    </ResponseField>
    <ResponseField name="content[].text" type="string">
      生成的文本,当 `type` 为 `"text"` 时存在。
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="stop_reason" type="string">
  生成停止的原因。常见值:`"end_turn"`、`"max_tokens"`、`"tool_use"`。
</ResponseField>

<ResponseField name="stop_sequence" type="string | null">
  触发生成结束的停止序列,或 `null`。
</ResponseField>

<ResponseField name="usage" type="object">
  用于计费和监控的 token 计数。

  <Expandable title="properties">
    <ResponseField name="usage.input_tokens" type="integer">
      输入消耗的 token 数。
    </ResponseField>
    <ResponseField name="usage.output_tokens" type="integer">
      响应中生成的 token 数。
    </ResponseField>
  </Expandable>
</ResponseField>
